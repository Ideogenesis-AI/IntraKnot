# `iknot cluster`

The `iknot cluster` command group discovers the available partitions, node hardware specs, and valid constraint values on the current cluster and persists them in `configs/cluster.yaml`. Use it to find the correct values for the `partition` and `constraint` fields in `slurm.toml`.

## Common workflow

```bash
# 1. Run once after `iknot init` (and again after the admin changes the cluster).
iknot cluster sync

# 2. Inspect the result to choose partition and constraint values.
iknot cluster show
```

Then open `configs/slurm.toml` (or the relevant campaign/run copy) and replace the `_init_` placeholders using what `iknot cluster show` reported.

## When to re-run `sync`

Run `iknot cluster sync` again whenever:

- The cluster administrator adds or removes nodes or partitions.
- You move your `configs/` directory to a different cluster.
- `cluster.yaml` is missing or you are unsure whether it is up to date.

`sync` always overwrites the existing `cluster.yaml`; the previous file is not backed up.

## Understanding the output of `iknot cluster show`

`iknot cluster show` prints two tables.

### Partition table

One block per partition, ordered as Slurm reports them. Each row is a hardware-uniform node group:

```
Partition: cluster [default]  state=up  timelimit=21-00:00:00
  NODES                   CPUS  MEM(GB)  GRES              FEATURES
  th-cl-hua[01-10]          32      125                    cascade
  th-cl-hua[11-29]          48      250                    cascade, avx512
  th-cl-rome01n[1-4]        64      500                    rome, epyc
```

- **NODES** — the node list in Slurm bracket notation. Use these names with `srun -w` for interactive sessions.
- **CPUS** — number of CPU cores per node; set `cpus_per_task` ≤ this value.
- **MEM(GB)** — memory per node in GB (rounded); set `mem` ≤ this value.
- **GRES** — GPU or other generic resource string; relevant for GPU jobs.
- **FEATURES** — the union of Slurm feature labels on nodes in this group. These are the valid values for the `constraint` field in `slurm.toml`.

Nodes are grouped first by name prefix (e.g. `th-cl-hua`), then split by hardware specs. If nodes under the same prefix have different memory or CPU counts, they appear as separate rows.

> **Note on features.** Feature labels are assigned by the cluster admin and are not guaranteed to identify hardware uniquely. If you see the same feature label on two rows with different specs (e.g. two `epyc` rows in one partition), the node group table is the authoritative source of hardware specs — use the `constraint` value to target those specific nodes and ensure your resource request matches their actual specs.

### Feature / Constraints table

A cross-partition index of all feature labels:

```
Features / Constraints:
  FEATURE    PARTITIONS              NODES
  cascade    cluster                    29
  epyc       cluster, small             56
  rome       cluster                     4
```

- **FEATURE** — a valid value for `constraint` in `slurm.toml`.
- **PARTITIONS** — which partitions contain at least one node tagged with this feature.
- **NODES** — total node count across those partitions.

## Translating `iknot cluster show` output to `slurm.toml`

Example: you want a CPU job on Rome nodes with 64 cores and 500 GB RAM, running up to 21 days.

1. From the partition table, find the row with `CPUS=64` and `MEM(GB)~500`. The feature label is `rome`.
2. The partition name is `cluster`.
3. Set in `slurm.toml`:

```toml
[main]
partition     = "cluster"
constraint    = "rome"
time          = "21-00:00:00"
mem           = "500000"
cpus_per_task = 64
```

If you want no constraint (any node in the partition), set `constraint = ""` to omit the `#SBATCH --constraint` directive entirely.

## `configs/cluster.yaml`

`cluster.yaml` is auto-generated by `iknot cluster sync` and should not be edited by hand. It is already excluded from git by the `configs/.gitignore` written during `iknot init`.

The file structure mirrors `iknot cluster show`: a top-level `partitions` list with `node_groups` entries, and a `features` dict for the cross-partition index.

```yaml
# Auto-generated by `iknot cluster sync`. Do not edit manually.
discovered_at: "2026-05-26T01:53:00+00:00"
hostname: "login.mycluster.example.com"

partitions:
  - name: cluster
    state: up
    default: true
    time_limit: "21-00:00:00"
    node_groups:
      - nodes: "th-cl-hua[01-10]"
        cpus: 32
        mem_mb: 128000
        gres: ""
        features: [cascade]

features:
  cascade:
    partitions: [cluster]
    node_count: 10
```

`mem_mb` is in MB; divide by 1000 to get the approximate GB value shown in `iknot cluster show`.

## Reference

### `iknot cluster sync`

```
iknot cluster sync [OPTIONS]
```

Runs `sinfo` and writes `configs/cluster.yaml`. Exits with a non-zero status and a descriptive error message if `sinfo` is not found (e.g. on a local workstation without Slurm).

| Option | Default | Description |
|---|---|---|
| `--machine PATH` | `./configs` | Path to the configs directory to write `cluster.yaml` into. |

### `iknot cluster show`

```
iknot cluster show [OPTIONS]
```

Pretty-prints the stored `cluster.yaml` as partition and feature tables. Exits with a non-zero status and an informative message when `cluster.yaml` does not exist.

| Option | Default | Description |
|---|---|---|
| `--machine PATH` | `./configs` | Path to the configs directory containing `cluster.yaml`. |
